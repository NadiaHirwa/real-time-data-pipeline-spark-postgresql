# Data Dictionary

Describes every column in the `events` table (and, by extension, every generated CSV file) — its type, meaning, and the constraint enforced on it. See [`data_contract.md`](data_contract.md) for the enforceable validation rules derived from these constraints.

| Column | Type | Description | Constraint |
|---|---|---|---|
| `event_id` | UUID/string | Unique identifier for this event | PRIMARY KEY, NOT NULL, must match standard UUID format |
| `user_id` | Integer | Identifier of the customer who triggered the event | NOT NULL |
| `product_id` | Integer | Identifier of the product involved | NOT NULL |
| `event_type` | String | The kind of interaction: `view` or `purchase` | CHECK IN ('view', 'purchase') |
| `price` | Decimal | Product price at the time of the event, in USD | CHECK >= 0, MUST be <= 10,000.00 |
| `quantity` | Integer | Units involved | CHECK > 0, MUST be <= 100 |
| `category` | String | Product category (e.g. "Electronics", "Books") | Nullable |
| `event_timestamp` | Timestamp | When the event actually occurred (event time), as generated by `data_generator.py` | NOT NULL |
| `ingested_at` | Timestamp | When Spark processed and wrote this row (processing time) | NOT NULL, defaults to insertion time |

## The `rejected_events` Table

Quarantined rows land here instead of `events`. Every value column is `TEXT`, and deliberately so: this table records what was **actually received**, not a cleaned-up interpretation of it. A `price` of `not_a_number` is exactly what a reviewer needs to see, and could not be stored in a `NUMERIC` column at all.

| Column | Type | Description |
|---|---|---|
| `event_id` | TEXT | The original event_id string as received, valid UUID or not |
| `user_id` | TEXT | The **original** string, before casting - e.g. `abc_user`, not NULL |
| `product_id` | TEXT | The original string, before casting |
| `event_type` | TEXT | Normalized to lowercase and trimmed, but never nulled |
| `price` | TEXT | The **original** string, before casting - e.g. `not_a_number`, not NULL |
| `quantity` | TEXT | The original string, before casting |
| `category` | TEXT | Trimmed; not validated (see data_contract.md) |
| `event_timestamp` | TEXT | The **original** string, before parsing - e.g. `not_a_timestamp`, not NULL |
| `corrupt_record` | TEXT | The raw CSV line Spark could not structurally parse; populated only for `malformed_csv_row` rejections, where it is the sole surviving diagnostic |
| `rejection_reason` | TEXT | Which contract rule the row violated; NOT NULL |
| `rejected_at` | Timestamp | When the row was quarantined; defaults to insertion time |

Original values are preserved because `cast_and_normalize()` copies each cast-prone column to a `raw_<name>` column *before* `try_cast()` overwrites it with NULL. Validation still runs against the typed columns; only the write to this table reads the raw copies. Before this was added, a rejected row showed that a field had failed but not what the value was — the verdict without the evidence.

## Notes on Event vs. Processing Time

`event_timestamp` and `ingested_at` are deliberately kept as two separate columns rather than one. In a real streaming system these can differ — a file might sit in the landing folder for a few seconds before Spark's next micro-batch trigger picks it up. Keeping both allows:
- Honest latency measurement: `ingested_at - event_timestamp`
- Correct historical analysis if the pipeline is ever paused and later resumes processing older files
